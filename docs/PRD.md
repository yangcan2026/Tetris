# 俄罗斯方块（Tetris）产品需求文档（PRD）

- 版本：v1.0
- 日期：2026-09-03
- 产品形态：桌面单机游戏（Python/pygame 版 + C++/Win32 版，双实现同等功能）
- 文档范围：以现有代码实现为准，描述产品的业务目标、功能需求、交互与规则。

---

## 1. 产品概述

### 1.1 产品定位
一款经典俄罗斯方块桌面单机游戏。面向桌面用户，提供标准俄罗斯方块玩法，并额外内置「AI 自动托管」能力，让用户既能亲自游玩，也可旁观电脑自动演示高质量对局。

### 1.2 产品目标
- 提供完整、可玩的标准俄罗斯方块体验（7 种标准方块、消行计分、等级与速度）。
- 提供辅助视觉（影子预览、下一个方块预览）降低上手难度。
- 提供 AI 自动托管模式，用于演示与娱乐。
- 以 Python 与 C++ 双实现保证跨环境覆盖（Python 侧重可读与可移植，C++ 侧重 Windows 原生原生性能）。

### 1.3 非目标
- 不包含网络对战、排行榜、账号系统、存档系统。
- 不含音效与动画特效（除绘制层面的 3D 立体色块效果外）。
- 不含难度曲线自定义、方块序列（7-bag）随机等进阶玩法。

---

## 2. 用户与场景

### 2.1 目标用户
- 希望快速体验经典俄罗斯方块的休闲玩家。
- 希望观察 AI 自动玩法的用户。

### 2.2 典型使用场景
1. 打开程序即进入一局新游戏，使用方向键/空格操作方块。
2. 软件自动随时间下落方块，玩家通过移动、旋转、加速下落实时操作。
3. 玩家可在任意时刻点击「托管」按钮，将控制权交给内置 AI 自动游玩。
4. 棋盘堆满后游戏结束，按 R 重新开始。

## 4. 功能详细需求

### 4.1 游戏操作（F1-F6）

**输入绑定：**

| 按键 | 行为 |
| --- | --- |
| ← / → | 向左 / 向右移动一格（合法时） |
| ↓ | 软降一格，且该动作反馈 1 分 |
| ↑ | 顺时针旋转 90°，自带墙踢（尝试原位置、偏左一格、偏右一格） |
| Space | 硬降：垂直落底后立即锁定 |
| P | 暂停 / 继续 |
| R | 重新开始（游戏结束后亦可使用） |

**移动/旋转规则：**
- 任意移动、旋转、下落均需通过碰撞检测（不越界、不与已固定方块重叠）。
- 旋转采用「SRS 风格简易墙踢」：先试原坐标，再依次试 `x-1`、`x+1`。

**下落与锁定：**
- 自动下落按 `fall_speed` 间隔触发（初始 1000ms）。
- 方块无法继续下移时即锁定写入棋盘，随后消行、切换下一方块、生成新方块。
- 软降（↓）/硬降（Space）与自动下落共用同一锁定流程。

### 4.2 消行与计分（F6、F7）

- 每行满 10 格视为满行，允许多行同时消除（最多四行）。
- 消行计分表（乘以当前等级 bonus）：

| 消除行数 | 基础分 |
| --- | --- |
| 1 | 100 |
| 2 | 300 |
| 3 | 500 |
| 4（Tetris） | 800 |

- 等级 = `累计消行数 ÷ 10 + 1`（向上由整除计算）。
- 下落速度随等级降低：`fall_speed = max(200, 1000 - (level - 1) × 80)` ms，即每升一级快 80ms，下限 200ms。

### 4.3 影子与下一个预览（F8、F9）

- **影子（Ghost）**：实时计算当前方块垂直落底位置，用浅绿色空心边框显示。若落点与当前位置相同则不绘制。
- **下一个（Next）**：侧边栏以更小格子（25px）绘制下一个待出方块。

### 4.4 暂停与重开（F10、F11）

- P 键在暂停/继续间切换；暂停时 `update` 逻辑（含 AI）一律不执行，仅渲染「暂停中」遮罩。
- R 键在任何状态（含游戏结束）重置所有状态并开始新局。

### 4.5 游戏结束判定（F12）

- 锁定后切换到新方块时，若新方块在初始生成位置（顶部中央）无法放置（与之重叠），则判定游戏结束。
- 结束画面：游戏区黑色半透明遮罩 + 居中显示「游戏结束」「最终得分」「按 R 重新开始」。
- 结束后停用全部自动下落 / AI 计时，仅响应 R。

### 4.6 AI 自动托管（F13）

**入口：** 侧边栏「托管 / 取消托管」按钮（点击鼠标左键切换）。

**行为：**
1. 开启后接管控制权，手动键盘操作被屏蔽（暂停与 R 除外）。
2. AI 对当前方块遍历旋转态与水平位置，模拟落底，用启发式评估选出「最优」落点。
3. 执行顺序：旋转对齐 → 水平移动 → 快速下落锁定，逐条动画执行。
4. 可视化：AI 的执行过程实时渲染，用户可旁观。

**评估函数（启发式 6 特征，加权求分后取最优）：**

| 特征 | 含义 | 权重 |
| --- | --- | --- |
| landing_height | 方块重心距底部高度 | -4.5 |
| eroded_cells | 消行数 × 本方块参与消行的格子数 | +3.4 |
| row_transitions | 每行中 0↔1 切换次数之和 | -3.2 |
| col_transitions | 每列中 0↔1 切换次数之和 | -3.2 |
| holes | 被上方方块覆盖的空格总数 | -7.9 |
| well_sums | 两侧受堵的井深度求和 | -1.2 |

- 综合分数 = `Σ(weight × feature)`，候选得分越高越优。
- 平局取「移动步数最少」的方案（旋转次数 + 水平距离）。

## 5. 界面布局需求

游戏窗口共 640 像素宽、800 像素高，分两块：

- **左侧游戏区（400×800）**：网格线、已固定方块、当前方块、影子预览、状态遮罩。
- **右侧侧边栏（宽 240）**：自上而下依次为——下一个预览框、「分数 / 等级 / 消除行数」三块信息板、操作提示列表、「托管 / 取消托管」按钮。

具体控件坐标（相对左侧 400px 起始）：

| 元素 | 位置（x, y） | 尺寸 |
| --- | --- | --- |
| 下一个预览框 | (425, 80) | 220×120 |
| 分数面板 | (425, 240) | 220×70 |
| 等级面板 | (425, 335) | 220×70 |
| 消行数面板 | (425, 430) | 220×70 |
| 操作提示 | (425, 550) | 逐行 28px |
| 托管按钮 | (415, 740) | 220×40 |

> 双版本（Python/C++）布局与坐标保持一致，仅渲染 API 不同。

## 6. 非功能需求

| 项 | 需求 |
| --- | --- |
| 帧率 | 渲染循环固定 60 FPS |
| 人机交互响应 | 键盘事件即时响应，输入无阻塞 |
| 中文显示 | 界面全中文；Python 版自动探测系统中文字体，C++ 版使用微软雅黑（UTF-8→UTF-16 转换） |
| 错误处理 | C++ 版对绘制资源（画刷/画笔/字体）使用后释放；窗口销毁时停止全部定时器 |
| 平台 | Python 版依赖 pygame；C++ 版依赖 Win32 API 与 GDI（仅 Windows） |

---

## 7. 需求约束与依赖

- Python 版运行依赖：`python3`、`pygame` 库、可选的中文字体。
- C++ 版构建依赖：Windows 平台、`windows.h`（WIN32_LEAN_AND_MEAN），编译期 C++11+（`constexpr`、`std::vector`、`std::mt19937`）。
- 本 PRD 完全基于现有代码行为归纳，不新增/删减功能。
